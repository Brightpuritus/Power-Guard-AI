# Power Guard AI

เว็บภาษาไทยสำหรับ XGBoost รุ่นล่าสุด รันภายในเครื่องด้วย Python backend และ HTML/CSS/JavaScript

## เปิดใช้งาน

จากโฟลเดอร์โปรเจค:

```powershell
.\venv\Scripts\python.exe web_v2/server.py
```

เปิด http://127.0.0.1:8765 หากพอร์ตถูกใช้ ให้เพิ่ม `--port 8766`

## ความสามารถ

- ภาพรวมชุดทดสอบ 6,356 ราย พร้อม Precision, Recall และ Precision@K
- ค้นหา กรอง จัดอันดับ และส่งออก CSV
- กราฟรายวัน พร้อมค่าเฉลี่ย 30 วัน และ SHAP รายมิเตอร์
- อัปโหลด CSV แบบ UTF-8 มี CONS_NO และคอลัมน์วันที่ 365–2,000 วัน สูงสุด 50,000 ราย/200 MB; FLAG เป็นตัวเลือก
- เปรียบเทียบผล XGBoost ล่าสุดกับ Logistic Regression และ Autoencoder

ใช้ `results_precision50/selected_p55.joblib` และขั้นตอน 74 Features ใน `experiment_missing.py` ค่า threshold จริงคือ 0.29896414279937744 แสดงผลเป็น 0.2990; SHAP ใช้ต้นไม้ถึง best_iteration ให้ตรงกับการทำนาย

ต้องเก็บไฟล์โมเดล, results_all_updated/features.csv, metrics_table.csv, results_precision50/test_predictions.csv, test_comparison.csv และ data.csv ไว้ตามตำแหน่งเดิม การเปิดรายละเอียดครั้งแรกอาจช้าขณะอ่านประวัติรายวัน

ไฟล์อัปโหลดเก็บในฐานข้อมูลภายในเครื่อง และเลือกกลับมาทำงานต่อได้จากเมนูชุดข้อมูล ค่าติดลบ/ไม่ใช่ตัวเลขถือเป็นข้อมูลขาด โดยไม่แทนด้วยศูนย์ คะแนนไม่ได้ผ่าน probability calibration และต้องยืนยันผลด้วยการตรวจสอบจริง ผลทดสอบเดิมถูกใช้ระหว่างพัฒนาแล้ว จึงควรทดสอบกับข้อมูลใหม่ก่อนใช้งานภาคสนาม

เซิร์ฟเวอร์เปิดเฉพาะ localhost ยังไม่ได้ติดตั้งบนอินเทอร์เน็ตหรือเพิ่มระบบผู้ใช้ เว็บเดิม app.py ยังคงอยู่

## ระบบติดตามงานตรวจสอบ

หน้าแรกแสดงคิวงาน รอตรวจ กำลังดำเนินการ และตรวจแล้ว คิวรวมมิเตอร์ที่ผ่านเกณฑ์โมเดลและมิเตอร์อื่นที่เริ่มทำงานแล้ว ผลคัดกรองไม่ใช่สถานะงานหรือผลตรวจยืนยัน

เปิดรายละเอียดมิเตอร์ ระบุชื่อผู้บันทึก สถานะ และหมายเหตุ หากเลือกตรวจแล้ว ต้องระบุวันที่ตรวจและผลตรวจ (พบ / ไม่พบ / ยังสรุปไม่ได้) ระบบเก็บทุก revision และป้องกันการบันทึกทับข้อมูลที่ถูกแก้ไขโดยอีกหน้าต่างแล้ว ชื่อผู้บันทึกเป็นข้อความที่กรอกเอง ยังไม่มีระบบ login หรือสิทธิ์ผู้ใช้

ข้อมูลเก็บใน `local_data/inspections.sqlite3` ซึ่ง Git ไม่ติดตาม รวมทั้งไฟล์ CSV อัปโหลด ผลตรวจ และประวัติ ปิดเซิร์ฟเวอร์ก่อนสำรองไฟล์ฐานข้อมูลนี้ ชุด SGCC ใช้ namespace `test` แยกจากชุดอัปโหลดด้วย UUID; อัปโหลดไฟล์เดิมซ้ำจะเป็นงานคนละชุด ให้เลือกชุดเดิมจากเมนูเพื่อทำงานต่อ การเปิดเว็บเริ่มต้นที่หน้านำเข้าข้อมูลเสมอ ยังไม่เลือกชุดข้อมูล และโหลด SGCC เฉพาะเมื่อเลือกชุดสาธิตจากเมนู

ไม่ต้องติดตั้งไลบรารีเพิ่มสำหรับ SQLite รุ่นนี้ยังรันเฉพาะ localhost และยังไม่ใช่ระบบหลายผู้ใช้ที่มีการยืนยันตัวตน


### ตรวจข้อมูลก่อนนำเข้า
เลือก CSV แล้วตั้งชื่อชุดข้อมูล (1–120 ตัวอักษร) กดตรวจสอบไฟล์เพื่อดูจำนวนมิเตอร์ จำนวนวัน ช่วงวันที่ และสัดส่วนข้อมูลขาด ก่อนกดยืนยันนำเข้าและวิเคราะห์ การตรวจสอบยังไม่บันทึกชุดข้อมูลหรือเรียกโมเดล

ไฟล์ที่มีรหัสว่าง/ซ้ำ วันที่ผิดหรือซ้ำ FLAG ไม่ถูกต้อง หรือมีมิเตอร์ที่ไม่มีค่าการใช้ไฟที่ใช้ได้ จะถูกปฏิเสธ ค่าว่าง ค่าที่ไม่ใช่ตัวเลข ค่าติดลบ และค่าไม่จำกัดถือเป็นข้อมูลขาดและแสดงคำเตือน

ตรวจไฟล์ซ้ำด้วย SHA-256 จากเนื้อหาไฟล์ทุกไบต์ (เปลี่ยนชื่อไฟล์ก็ยังตรวจพบ แต่เปลี่ยนรูปแบบ CSV อาจไม่พบ) ผู้ใช้เปิดชุดเดิมได้ หรือยืนยันนำเข้าซ้ำเป็นชุดใหม่ที่มีผลตรวจสอบแยกกัน ฐานข้อมูลเดิมจะเพิ่มดัชนีไฟล์ซ้ำโดยรักษาข้อมูลที่บันทึกไว้
